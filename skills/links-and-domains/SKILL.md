Use this skill when the user wants to manage their public link page, customize its look or blocks, attach a Pro custom domain, remove Spica Post branding, shorten links for click tracking, or publish a sponsor media kit.

1. Call `brands_list` first (when the login holds multiple brands, confirm which one and pass `brandId` on every call).
2. Inspect current state with `links_list` (or the `spica://workspace/links` / `spica://brands/{brandId}/links` resources, plus `brand_get`, `short_links_list`, or `media_kit_get` when relevant). Note `kept.starter` on `links_list` for suggested handle, bio, website, phone, brand items and brand photo IDs. If the user is migrating from Linktree, Beacons or another bio page, call `links_import` with its URL first (read-only) to extract their existing bio, social icons and links. You can also start from the `build_link_page` guided prompt.
3. **Link page, custom boxes, social icons, visual theme & QR code**:
   - Use `links_save` to set the handle, name, bio, ordered `links` (standard link buttons, custom boxes with `kind: "box"` + optional `body`/`image`/`url`/`cta`, which work with or without a link, `layout`: `stack`/`compact`/`half` for 2-column Bento pairing, optional `startsAt`/`endsAt` schedule for timed promos, and section headings with `kind: "heading"`), quick additions via `addLink` (also supports `layout`: `stack`/`half` and `startsAt`/`endsAt`) or `addBox`, manual `socials` icons (17 platforms), and per-page `theme` (`surface`: `brand`/`tint`/`dark`/`clean`, `font`: `brand`/`editorial`/`modern`/`bold`/`mono`, `buttons`: `pill`/`rounded`/`square`, `buttonFill`: `outline`/`solid`, optional `colors`, `avatar`, or `cover`).
   - Also supports `showPosts`, `showHours`, `showBlog`, and `hideBranding: true` (Pro white-label removing "Made with Spica Post" from the link page, blog and media kit).
   - Call `links_qr` to generate a scannable SVG QR code for the link page (or its verified Pro custom domain), styled with the page's theme/brand colours or high-contrast black on white for printing.
   - Hand the user the `editorLink` (`/links`) so they can preview and tweak the page visually anytime, and always ask the user before publishing (`published: true`) or deleting (`links_delete`).
4. **Pro custom domain**:
   - Call `links_domain_set` with the link page `id` and clean hostname (such as `links.yourbusiness.com` or `yourbusiness.com`). Ask the user before changing an already live custom domain.
   - Show the user the exact TXT record (`_spica-verify.<host>` → `spica-verify=<token>`) and CNAME record (`<host>` → `app.spicapost.com`, or ALIAS/ANAME/flattened A record for apex domains) to add at their registrar.
   - Once the user says DNS records are added, call `links_domain_verify`. Once verified, the domain serves `/`, `/blog`, `/blog/<slug>`, `/media-kit` and `/robots.txt` with white-label branding and canonical URLs.
   - Only call `links_domain_remove` after explicit confirmation.
5. **Tracked short links & dynamic QR codes (Studio, Pro and Agency)**: Use `short_links_save` to create `/l/<code>` URLs tied to a `draftId`, `postId`, `autoreplyRuleId` or offline sign/flyer (such as a direct Google Review link or menu PDF), call `short_links_qr` to generate a dynamic brand-styled or print SVG QR code whose destination can be updated later via `short_links_save` without reprinting the sign, and use `short_links_list` (or `results_get`) to report human scan/click counts. Ask before calling `short_links_delete`.
6. **Sponsor media kit (Pro and Agency)**: Read `media_kit_get` and `results_get`, draft the headline, sponsor intro, contact link and optional self-reported audience or package rows without inventing numbers, show the full preview, and ask before saving `published: true` via `media_kit_save`.
